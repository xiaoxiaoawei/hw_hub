# 软件更新与手动升级

FlashTool 从本仓库的正式 GitHub Release 获取更新。下载和重启安装分别由用户确认，升级保留当前用户的软件设置、CSV 和固件文件。

## 先从旧版升级

**v0.5.0 及更早版本没有程序内下载与替换能力，首次需要手动安装 v0.5.1 或更新的正式版本。** 旧版“检查更新”提供的浏览器下载入口不会自动获得新安装流程。

1. 打开[官方最新正式发布](https://github.com/xiaoxiaoawei/hw_hub/releases/latest)，下载该版本的 Windows x64 ZIP。保留同一发布的 SHA256SUMS，按需核对下载文件。
2. 等待本批烧录和本地 CSV 保存完成，再退出旧 FlashTool。
3. 将 ZIP 解压到当前用户可写的普通目录，运行其中的 FlashTool.exe。也可在退出旧版后备份原文件，再使用完整新版发布包替换。
4. 软件设置和自动设备记录位于用户的 FlashTool 数据目录。保留这些目录即可继续使用现有设置与 CSV；无需把旧目录中的日志或固件复制进程序目录。

## v0.5.1 起的程序内更新

从主界面右下角齿轮打开“软件设置”，点击“检查软件更新”。发现更高的正式版本后，先查看版本号及说明，再选择“下载更新”或“稍后”。

下载在后台进行，界面显示下载进度。客户端取得同版本的官方 Windows ZIP 与 SHA256SUMS，核对完整发布包校验和、目标程序的 Windows x64 GUI 类型及内嵌版本。下载失败或校验失败时保留当前程序，并显示原因和重试/官方发布入口。

当前校验文件上限为 64 KiB、Windows ZIP 上限为 128 MiB；每项资源下载链最长 120 秒，最多接受 5 次受信 HTTPS 跳转。更新包中的版本元数据必须与所选正式版本一致。

校验通过后提示“重启更新”，也可选择“稍后”继续使用当前版本。烧录、驱动安装或本地 CSV 保存尚未完成，以及仍有本地记录保存失败时，不允许重启；先完成任务或在设置中重试保存。下载与重启安装是两个独立步骤，发现新版不会直接结束当前程序。

本地记录已保存、仅远程上传未完成时，会显示剩余条数；此时确认重启会中断这些上传。CSV 保留，程序下次启动不会自动扫描并补发历史 CSV。可以先等待上传完成，再重启。

确认“重启更新”后进入助手准备阶段，按钮改为“隐藏”。隐藏只关闭提示窗口，已经提交的更新准备会继续；助手就绪并再次通过安全条件后，程序退出进入安装。

## 安装与恢复

程序内安装适用于当前用户可写的便携版目录。程序目录不可写、文件只读或运行权限不符合更新条件时，保留手动下载入口，不自动请求管理员权限。

更新助手准备就绪后，旧程序才退出。助手最多等待旧进程结束 60 秒，不强行结束旧进程；在替换边界重新核对下载文件和目标，再备份旧程序及需要覆盖的白名单说明文件、替换并启动新版。新版正常初始化后向助手确认启动；未能确认启动、替换失败或启动失败时，按错误路径保留或恢复旧版，并说明恢复结果。

助手准备确认最多等待 15 秒，新版初始化确认最多等待 30 秒。成功后保留备份和安装成功记录，失败时保留安装日志；这些结果用于实际故障恢复，不把“进程已启动”直接视为升级成功。

更新保留本机软件设置、设备 CSV 和用户固件。不要为解决更新错误删除整个 FlashTool 用户数据目录；可先复制错误详情，再从官方 Release 手动安装。

如果错误明确提示回滚失败，按提示中的备份路径手动恢复旧文件，或退出后重新解压官方发布包。

更新文件和错误信息保留在本次暂存目录，错误提示会给出目录路径：

| 文件或目录 | 用途 |
| --- | --- |
| %LOCALAPPDATA%\FlashTool\updates\update-* | 本次下载、校验、助手和安装清单的暂存目录。 |
| download-error.txt | 下载或准备失败的原因。 |
| install.log、install-error.txt | 安装步骤及错误；错误信息可能包含手动恢复所需备份路径。 |
| install-success.json | 新版界面初始化确认成功的记录。 |
| 程序同目录的 .FlashTool-update-backup-* | 被覆盖程序和白名单说明文件的旧副本；成功后也保留。 |

## 来源与验证范围

更新只接受本仓库对应正式版本的资产，使用正常 HTTPS 证书校验，并核对版本和 SHA256；分支、Actions 构建产物、草稿或预发布不作为正式升级来源。版本按数字比较，过期更新信息不会触发降级。

程序内更新的本地验证、原生 Windows 构建/回归与真实目标电脑上的升级验收分别记录。Windows 权限、杀毒软件、安装路径及设备占用仍应在目标电脑验证。USB Hub 插拔与多设备烧录的验收范围见 [README](../README.md#验证边界)。

设备日志上传与软件更新使用独立配置，上传接口见[设备日志上传接口](log-upload-api.md)。软件更新不向更新服务器发送这些自定义上报请求头或设备日志。
